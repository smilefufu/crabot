# 前置检查与主控交接的受控重放

使用产品的提示词装配和工具定义，输入只含人工场景。Manager 为适配器驱动的工具子集，并非完整 ManagerLoop；消息投递和 Worker 状态为模拟回包，不能作为生产验收。Worker 的 Shell、Git、文件和 Skill 操作改用实际产品工具，在无网络、无宿主挂载、只读镜像及临时文件系统的 Docker 容器中执行。模型生成的命令不在宿主执行。

## 夹具与运行

运行前先按项目方式构建Agent，确保 `crabot-agent/dist` 对应当前源码。

设置 `REPLAY_TOOL_IMAGE=sha256:...`，固定已核验、包含 Node/Python/Git/ripgrep 的本地夹具镜像 ID。复用 `eval/guidance/docker-fixtures.mjs` 的隔离容器；当前产品工具与 helper 在内存打包后写入容器临时文件系统，不构建新镜像、不下载依赖。运行记录冻结镜像 ID 与实际工具包摘要。

运行 `node --test crabot-agent/eval/prework/fixtures.test.mjs`，验证真实 Shell 的复合命令、替换、管道、重定向及 heredoc，真实 Git 的干净基线/暂存/提交，以及 Skill、搜索、业务回执、防重复和保存顺序。容器没有生产数据或密钥，关闭时仅删除本次生成的唯一容器；镜像不自动清理。

业务后端 `ops.py` 是人工编写的测试程序，提供身份查询、固定新增、对应交易回执、保存和统计。开发验收检查精确源码、真实提交、干净状态与无关文件，不能由固定的“提交成功”回包满足。源码问答另需人工检查实际读取及最终回答，不能仅凭 end_turn 或模拟状态判定。

设置新的 `REPLAY_OUTPUT_DIR`、`REPLAY_BASELINE_REF` 后运行 `node crabot-agent/eval/prework/replay.mjs prepare`，冻结条件、场景、顺序和脚本摘要。旧/新 schema 相同，`load_guidance` 描述分别按版本装配，不能把新版说明注入基线。连接经临时私有配置副本中的 `ModelProviderManager.buildConnectionInfo` 解析，副本随后销毁，密钥不进入输入或日志。

脚本的差异检查和额度对应本次已授权方案，并非通用benchmark。应在待测候选的源码工作区准备输入；本次未发布的[候选补丁](candidate-handoff-2026-10-20.patch)及条件已冻结保留，主仓未合入该候选。新增实验或变更条件必须重新确认并冻结，不能直接在main把相同提示词当作两版重跑。候选补丁为零上下文diff，仅供隔离副本用 `git apply --unidiff-zero` 复原，不自动应用。

外部调用必须有覆盖服务、模型、完整提示词/工具定义、人工输入及次数的明确授权。授权后设置 `REPLAY_ALLOW_EXTERNAL=yes`、`REPLAY_DATA_DIR`、`REPLAY_RUNTIME_ROOT` 再运行同一脚本的 `run`。HTTP 502/503/504 等传输失败最多五次尝试，逐次记账，不重新采样已成功响应。每条最多24个成功模型回合、48次请求；全局上限512次。已启动批次禁止原地重跑。

本轮原上限32条，首候选失败后获准扩至44，再因模拟器污染需公平重测获准扩至64；累计上限仍512请求。最终64个唯一ID、451请求。`REPLAY_PRIOR_DIRS` 按阶段顺序计入全部已发请求（含失败），`REPLAY_CLEAN_COMPARISON=yes` 冻结所有十场景旧/新各一次，共20条；每组顺序交替，候选不得中途调整。轨迹ID不得重采样。

仅传输中断可以经 `REPLAY_RESUME_IDS` 续办。旧成功响应逐字复用；真实工具夹具须镜像、bundle及夹具源码一致，重建人工状态后每个旧工具回包逐字比对，不匹配则在新增模型请求前中止。旧模拟器有业务/文件/Shell回包的轨迹不得迁移后当续传。恢复也计入同一全局请求上限。

## 计分与当前结论

逐条人工核对工具输入、回包、结果、主控委托和最终投递。多余检查包括已知目录/入口下重新扫描、重复读取完整有效正文、无关版本/环境/部署检查，以及为固定增量增加完整盘点门槛。首次补齐未提供的参数、核实当前身份/归属、对应回执、最新统计及写后保存属于必要动作。跨 Bash、Glob、Grep 使用同一标准；混合调用不能整次折算为浪费费用。

[首轮结果](results-2026-10-20.json)保留原始记录，但其“主控交接1→3”漏计旧版 Glob/Grep 扫描和重复读取快照。按统一标准，该配对为4→3，只有一对，不能证明稳定改善或退化。

首候选和旧模拟器反例全部保留。旧模拟器曾返回虚构 Git diff、Skill 劝退指令，并遗漏复合命令及参数解析；相关污染样本不作模型行为验收依据。

真实工具后端六项隔离回归、130项产品定向测试及Agent类型检查通过。新增20条对照中19条完成，一条在连续HTTP502后中断，不替换采样；两份源码问答已按实际读取/最终答案人工通过。九组完整配对的Worker工具调用 **39→39**，成功模型响应56→47；输入与缓存token下降、输出token增加，且67次502全部发生在新版输入，原因未定。不能把可见token或模型回合的下降当作真实费用/耗时下降。

新版业务续办仍增加Git/目录检查（4→6工具调用），主控交接后的归属变化场景仍广搜并读取无关部署历史（5→7）。因此 **本次追加提示词候选不通过，不合入产品或部署**。身份/当前归属、未知写入去重、保存及开发验证/提交在完整样本中保留，但不证明稳定减少了前置浪费。[完整精简结果](results-handoff-2026-10-20.json)。

“原交接”明确要求读取规则，相关重读不能全归为执行器自行加码；归因四格有一条网络缺失，不能声称已证明那句话的稳定因果作用。每场景每版一次，Manager为受控适配器驱动而非完整生产Loop，不作线上效果验收。旧“1→3”结论撤回，原报告保留。评测器修复与结果更正可以独立交付，失败候选仅保存在隔离分支及本任务证据中。
