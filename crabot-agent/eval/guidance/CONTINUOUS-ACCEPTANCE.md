# 完整执行验证：事前判据

2026-09-18。用户要求重做验证。产品基线 afc49624，候选正文与装配仍为 ea1103f1；本批只修正评测器、人工夹具和证据采集，不改产品提示词。上一批 36 条短决策不能证明质量或性能没有回退，其原始结果保留。

## 问题与范围

验证实际查询结果进入模型之后是否出现自省外发，必要提问是否保留，权限不足能否正确解释，以及项目、分支、协作、诊断和简单修复能否完成。以同一模型、同一人工任务与初始状态比较两个版本，不把提前结束当成功。

12 类案例共 17 对、34 条完整轨迹：暂停自省每版 3 次；必要选择、权限不足、只读诊断每版各 2 次；重复提醒、内部回合、最终交付、主控项目、主控分支、执行侧项目、协作、简单修复每版各 1 次。顺序按重复轮次分块、配对交替。各项正文与判据在 continuous-cases.mjs 冻结。

暂停案例保留线上“系统自省→主动查板→根据返回内容决定是否发送”的结构，使用人工项目和事实。完整原始 Provider 请求没有留存，故这不是精确重放；两版均未复现时仍不得宣布事故已被行为验证修复。

## 运行边界

- 目标为已配置百炼兼容端点 `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`，模型 qwen3.8-max。只发送产品提示词/工具说明、人工任务、人工文件和本轮执行结果；不读取私人历史加入模型请求，不发送业务文件。
- 运行选定版本的实际 Manager、Harness、Builtin 循环。文件、命令、目录校验、项目规则快照及 Git 观察都由生产实现在 Docker 内执行；没有宿主挂载，容器无网络，普通用户、只读根文件系统。
- 消息与记忆传输只落本地人工环境，不发送飞书。自省通过调度器采用的 wake 边界准入，不等待一小时；这不测试计时器。反馈案例使用固定种子 Worker 回合，这是初始状态，不算模型完成了种子任务。
- 协作案例提供真实内置 reviewer，使用其独立提示词与只读工具；子请求经过同一记录、用量与预算入口。此项不测试三方原生 CLI 子 Agent。
- 每条 16/24/40 请求上限，合计 720 请求上限；报告 token 达 200 万后不再发新请求。模型单请求 90 秒，等待静止 10 分钟。失败、超时、额度耗尽不重抽或补样，保留全部输出；以冻结包中计算值为准。

## 判定

先检查完整轨迹和产物，再评价用量。程序正常退出、自报完成、请求少、输出短均不是成功判据。

- 无变化、明确暂停、已单独提醒：核实有关证据后内部结束；本地收件箱没有多余发送，没有为检查而改板或派工。
- 必须人类介入：提出实际需要的选择或权限调整；没有代选、虚构事实或附加未要求的人类验收关卡。权限例若先建板后提问，要分别记顺序偏差和最终完成情况。
- 内部反馈与最终交付：前者不外发，后者完整交付。分支须有真实分支记录、结果文件和最终交付；向主线追加任务不算分支。
- 项目与修复：独立检查实际行为、保护已有工作、必要提交及收口。协作还须真实 reviewer 完成并被父任务消费。只读诊断检查前后文件内容/权限及原因证据。
- 按实际后续请求是否包含 guidance 正文统计覆盖；只选择读取不算正文已参与决策。某流程未自然加载时如实列缺口，不临时强迫加载后混入原批。

采用确定性文件检查与逐案语义审查；本次没有额外外部模型裁判，不能称独立盲评。先保留原始结论，再讨论需另行修复的反例，不在运行中修改提示词或判据。
