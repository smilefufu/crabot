## 结论口径

- 工程装配正确、有限案例决策符合要求、完整任务质量不退步，是三个不同结论。
- 第一阶段只检查决策，不能以派发、选择读取或声明完成冒充真实执行和交付。
- 目前的普通任务退步界限建议为完成率下降 5 个百分点。正式统计验收必须先固定代表性抽样方法、指标、样本量、总预算和区间计算方法；本轮十个选定案例不满足这一条件，不计算泛化通过率，不宣称质量等价。
- 先前“零不利配对约需 59 对”的数值只适用于独立同分布的零事件二项上界示例，约束“旧成功、新失败”的概率；不是通用的两版本完成率差异样本量公式。重复同一道题不能当作新增业务场景。
- 严重越权、虚报完成、破坏已有工作单列；不得用较低成本抵消。一次错误不能自动归因为提示词退化。

## 第零阶段：修复测量干扰

1. 请求预算到顶只拒绝后续新请求，不取消此前已准入的响应；等已准入请求和运行回合收口后清理。仍保留单请求与等待超时，预算不足单独记录。
2. Docker 进程/线程上限从 64 调整为 256，保留无网络、无宿主挂载、普通用户、只读根、256 MiB 内存与 1 CPU。用实际六路 Read 和 cgroup 计数检查，不借修改提示词让模型少并发来绕过夹具问题。
3. 两项修复均先出现定向失败，修复后连同原本地链路共 9 项通过。原模型日志和原比较结果不回写，也不自动补跑原失败。
4. 主控读仅存在 Docker 内的路径、部分记忆 RPC 未实现，仍是旧完整链路装置的已知缺口。在下一阶段正式完整任务比较之前补齐或明确排除，不将这种错误算到提示词质量中。

只有静态 guidance、产品权限计算以及明确人工 Worker 观察可返回本地结果。其余工具调用只记录模型的选择，不执行，不返回虚构成功回执；Shell 不执行，消息不外发，Worker 不启动。首次业务选择或普通回答即结束；因此只能判断下一步，不能检查其后完整工作是否完成。若先选择取证，不能把尚未生成的交接判为正确或错误。

- 沿用百炼 `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`，固定 `qwen3.8-max` / OpenAI 兼容格式。默认模型即使改变也不混用，不修改配置。

### 判定与匿名审阅

先对每个输出按冻结标准标记“符合”“明确违反”或“证据不足”，引用具体内容；再比较 A/B 的语义表现。工具数、字数、是否读取指南都不能单独代表质量。额外询问、无用安排和范围膨胀作为过程负担单列。

结束时生成随机 A/B 标签的 `review-blinded.json`，映射单独保存在 `review-mapping.json`。人工标准不进入被测模型输入。标签隐藏不保证行为或措辞完全不透露版本；由当前助手自审也不属于独立评审，不能包装成独立盲评。需要人类校准的分歧明确保留。

## 第二阶段：完整任务验收的进入条件

第一阶段用于发现明显问题、决定后续投入，不负责宣布改造胜出。完整任务比较须先处理第零阶段剩余缺口，另外冻结有代表性的完整任务及费用预算；确认样本量是否足以排除约定幅度的退步。失败尝试成本计入总量，比较同时报告交付数量和完整成本。证据不足则保留“不确定”，不无限扩样，也不把第一阶段二十对当成完整任务样本。

第一阶段旧运行结束，实际 55 次请求、224,127 tokens，未超过上述边界；因后续确认的装配缺陷，不记为方案验收完成。原日志、判定和用量不重写。实现修复仅在本地，未合并、推送或部署；修复后的新增模型批次仍须冻结版本、具体范围和预算。
