## 2026-09-17 装配缺陷与证据处置

- 离线使用实际编译装配复现：在相同模型、会话、人格与档案下，普通场景切换为 Worker 反馈或任务板场景，system prompt 与 `prompt_cache_key` 均变化；普通 `load_guidance` 工具读取保持二者不变。前者不符合协议的静态 system prompt / 尾部事件和工具结果边界。未调用外部模型。
- 最新十项短决策比较中，`m-use-existing-approval/candidate/{1,2}` 与 `m-incomplete-result/candidate/{1,2}` 四条直接用了错误的 system 装配。历史完整链的两个主控案例、早期模拟中的 `idle-with-error/candidate` 也使用该路径；早期预检/模拟未使用通用缓存 key，但仍把指南放错位置。
- 受影响的不只是缓存统计：指南在 system 中的位置与权威层级也属于模型输入条件。受影响行为轨迹不能代表修复后实现；整批汇总不能替正确方案背书。尚未证明此缺陷造成了多少额外未缓存输入，也不能据此抹掉观察到的模型错误。
- 独立 Worker 工具加载路径没有触发此处缺陷，其实际产物与有限观察可作为该路径的历史证据保留，但不能由此恢复整体方案验收。原有模拟缺口、预算取消、Docker 并发限制等问题继续分别保留。
- 更正当时的状态：本地装配检查已通过，方案质量验收仍未通过；暂停追加模型比较，等待冻结修复版本和受影响案例。后续新批次见上文；没有推送、合并或部署。
