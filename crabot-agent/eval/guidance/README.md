# 内置 guidance 隔离比较

比较主控、执行侧在 6 个人工案例中的决策。业务工具全部返回固定模拟结果；`compare.mjs` 仅实际调用无副作用的产品 guidance 读取。不会读取真实聊天、业务文件或启动执行器，不执行模型给出的 Shell 命令。

这是有限的决策比较，不是生产任务验收。`response-ended` / `decision-observed` 只表示轨迹停止；必须检查输出、工具调用和证据，不能作为成功计数。`harness_gap`、请求失败和轮次上限分别保留，不自动重试或补样。案例只有每版一次，不能据此推断稳定性或泛化提升。

## 准备与运行

先构建 Agent。`--prepare` 只生成请求包，不读取运行配置、不连接模型。真实运行会使用现有 Admin 连接解析器，限定当前已核对的百炼端点和 Qwen3.8-max；密钥只进入请求头，不写入产物。

1. `preflight.mjs --prepare`：设置 `GUIDANCE_BASELINE_REF` 为改动前 commit、`GUIDANCE_SPEC` 为确认稿、`GUIDANCE_OUTPUT` 为新目录。旧正文通过 `git show` 固定在指定版本，不依赖当前工作区。首轮上限为 12 条轨迹、48 次请求。
2. `compare.mjs --prepare`：设置 `GUIDANCE_FROZEN` 指向首轮 `inputs.json`、`GUIDANCE_OUTPUT` 为另一个新目录。基线沿用首轮，候选使用当前编译后的实际提示词及工具说明。双方均使用同一组工具说明与场景，候选另有 guidance；第二轮上限为 12 条轨迹、72 次请求。
3. 先核对 `inputs.json`、接收方、模型及发送范围。得到这次外部比较的具体授权后，保留上述变量，并设置 `REPLAY_RUNTIME_ROOT` 为已构建 Admin 所在仓库、`REPLAY_DATA_DIR` 为对应数据目录，移除 `--prepare` 运行同一脚本。

输出目录含 `inputs.json` 和逐请求 `events.jsonl`。输入有 SHA-256 摘要；再次使用准备目录必须逐字一致，已有运行日志则拒绝复跑，避免覆盖失败证据。产物默认仅本用户可读，勿将真实配置或凭据加入比较包。

第二轮比首轮补充真实消息投递说明及模拟复核、测试脚本读取与已观察的目录查询，并明确去重任务口径。因此两轮结果不能混合计分。仍未覆盖生产调度、真实投递、文件/Shell 执行及原生 CLI 子 Agent。
