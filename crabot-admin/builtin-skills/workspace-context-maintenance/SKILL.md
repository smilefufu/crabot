# 项目上下文维护

## 工作流程

1. 确认并遵守项目根目录的 `AGENTS.md`。它是跨执行器的项目规则入口；不要创建、替换或重写它。
2. 根据当前任务实际需要读取职责明确的现有文档：
   - 从 `README.md` 了解项目入口、运行方式和简短概览；
   - 从 `ARCHITECTURE.md` 了解组件边界、关键数据流、状态机和跨模块不变量；
   - 从项目已有的决策目录了解已经生效或被取代的决定；
   - 按任务读取协议、运行手册、贡献指南、设计文档和领域文档。
3. 先确认项目现有的目录和权威来源，不要根据文件名、旧计划或历史报告自行推断当前事实。
4. 发现长期项目事实、架构说明或引用缺失、过时、互相矛盾时，向主控说明具体缺口和证据。
5. 只有主控明确把一般项目文档更新纳入当前任务时，才在该范围内修改；完成后运行项目已有的文档检查，并报告可核实的修改结果。

## 边界

- 不自动创建 `AGENTS.md`，也不创建混合当前任务状态、项目事实、决策和交接内容的上下文文档。
- 不创建、修改、取代或迁移决策记录。执行过程中出现可能影响长期项目工作的决定时，把事实和建议报告给主控，由主控判断并管理决策文档。
- 不把执行日志、命令输出、临时阻塞或当前任务进度写入长期项目文档。
- 不要求每个任务都修改文档；没有长期文档变化时直接完成任务，不输出“无需更新文档”之类的仪式性说明。
- 不把旧报告、历史计划或名称含 `latest` 的文件直接当成当前权威，除非项目规则或当前文档明确指定。
